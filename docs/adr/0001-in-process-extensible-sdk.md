# In-Process Extensible Python SDK over External Script Runner

We built `gh-migration-tool` as an in-process, object-oriented Python SDK where variable customer-specific workflow stages (`PreCheck`, `GitHubSetup`, `Migrator`, and `PostCheck`) are defined as typed abstract interfaces, while invariant workflow stages (`Prepare`, `Inventory Update`, and `Migration Report`) remain concrete core engine steps. Writing customer customizations as typed SDK classes rather than orchestrating arbitrary external shell scripts allows engineers to contribute new checks, provisioners, and migrators back to the core repository via Pull Requests, compounding into a shared, tested catalog across future engagements without over-abstracting fixed pipeline mechanics.
