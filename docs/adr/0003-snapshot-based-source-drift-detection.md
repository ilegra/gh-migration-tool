# Snapshot-Based Source Drift Detection over Commit SHA Parity

Because `gh-repo-sync` filters origin-exclusive paths, protects destination-exclusive paths (such as `.github/`), and appends `[skip actions]` to commit messages during synchronization, the resulting commit SHAs on GitHub intentionally diverge from the commit SHAs on the origin SCM. Consequently, Post-checks cannot verify migration fidelity by comparing origin commit SHAs directly against destination commit SHAs. Instead, the workflow captures an in-memory `Origin Snapshot` (branch names and their tip commit SHAs) immediately before a Migration Unit's Migration stage starts, and Post-checks verify that no migrated branch has a newer commit SHA on the origin SCM and no new branches were created on the origin SCM while Migration was in flight.
